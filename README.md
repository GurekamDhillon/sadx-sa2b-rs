# sa-rewrite

Rust crates that read Sonic Adventure 2 (and, later, Sonic Adventure DX)
content from your own install, with a C ABI for C/C++ projects. It is the
foundation for a reusable character controller and Chao Garden simulation.

No game files are included. Everything is read at runtime from the install
you point it at, and game files are never modified.

## Crates

| Crate | What it does |
| --- | --- |
| `sa_formats` | File formats: PRS compression, PE32 address mapping, SA2 PC `.pak`, GVM/PVM archives, GVR/PVR/DDS textures to RGBA8, Ninja node trees, chunk/basic/GameCube models, motions, landtables, rest-pose flattening to triangle meshes. |
| `sa_data` | Game knowledge: install detection by exe hash, the physics table, character/upgrade/Chao enums, the character asset catalog, the SA2 Chao save format. |
| `sa_controller` | Character controller: the engine's ground/air acceleration, turning and speed integration decoded from SADX, driven by SA2 `PhysicsData`; stand/run/jump/fall/hurt actions; a `World` trait for your collision (plus a ready-made triangle-mesh world). See `docs/controller.md`. |
| `sa_ffi` | C ABI. Builds `sa_ffi.lib` (static) and `sa_ffi.dll`; `include/sa.h` is generated by cbindgen. |

## Supported builds

- **SA2 Steam** (`sonic2app.exe`, SHA-256 `4b1e09d7…2c16`): models, motions,
  textures, physics, all 104 landtables in `Data_DLL.dll`, Chao saves.
- **SADX 2004 US** (`sonic.exe`): detected; content loading is not
  implemented yet.
- **SADX 2011 Steam** (`Sonic Adventure DX.exe`): reported as unsupported.
  Convert it with [SA Mod Manager](https://github.com/X-Hax/SA-Mod-Manager).

## Using it from C

```c
#include "sa.h"

SaGame *g;
if (sa_game_open("D:/SteamLibrary/steamapps/common/Sonic Adventure 2", &g) != SA_STATUS_OK) {
    fprintf(stderr, "%s\n", sa_last_error());
}
SaPhysics p;
sa_physics(g, SA_CHARACTER_SONIC, &p);

SaMesh *m;
SaMeshView v;
sa_mesh_load_character(g, SA_CHARACTER_SONIC, SA_COSTUME_DEFAULT, &m);
sa_mesh_view(m, &v);            /* positions, normals, uvs, indices */
sa_mesh_free(m);
sa_game_close(g);
```

To drive a character from C, create a world with `sa_world_from_callbacks`
(your engine's ground and wall queries) or `sa_world_from_collision`, then
`sa_player_create` with physics from `sa_physics`, and call `sa_player_step`
once per 60 Hz frame.

Link `target/release/sa_ffi.lib` plus `kernel32 ntdll userenv ws2_32
dbghelp advapi32 bcrypt`, or use `sa_ffi.dll`. See `tests/ffi/main.c` for a
complete program.

## Building and testing

```sh
cargo build --release
cargo test                                   # no game files needed

# Against a real install:
SA2_DIR="D:/SteamLibrary/steamapps/common/Sonic Adventure 2" \
  cargo test -p sa_data --features game-tests
SA2_DIR="..." cargo test -p sa_ffi --test c_abi   # builds and runs main.c with MSVC
```

Probe tools (examples): `unprs`, `texprobe`, `modelprobe` (renders a model
to PNG), `landprobe`, `peexports` in `sa_formats`; `physics` in `sa_data`.

## Accuracy notes

- Struct layouts, addresses and enums come from the X-Hax
  [sa2-mod-loader](https://github.com/X-Hax/sa2-mod-loader) headers. Sonic's
  physics row was cross-checked byte for byte against a Ghidra read of
  `sonic2app.exe`.
- Every model, texture, motion, PRS file and landtable that the tests touch
  was parsed from a real Steam install.
- Not verified yet: where the Chao slot array starts inside `SONIC2B__ALF`
  (assumed 0xA64, from memory addresses), and what `ewalk2mdl.prs` is.
- Research notes: `docs/sa2_characters.md`, `docs/sa2_chao.md`, `docs/sadx.md`.

# SA Rewrite — Foundation Design (formats, data, C ABI)

Date: 2026-10-11

## Goal

A Rust library, modeled on chasmlol/2010-rust-rewrite-mashup, that reads Sonic
Adventure 2 and Sonic Adventure DX content from the user's own installs and
exposes it to Rust and to C/C++ (via a C ABI). The end goal is a reusable
character controller and Chao Garden simulation for a C/C++ project (PowerPC
code with Windows-native shims). This spec covers only the foundation those
systems need: file formats, game data, and the C ABI.

Later specs (separate cycles): `sa_controller`, `chao_sim`.

## Ground rules

- No Sega data is committed or shipped. Assets are read at runtime from the
  user's install.
- Game files are only read, never modified. The exe is read as a file, never
  from a running process.
- First target: SA2 PC Steam (`sonic2app.exe`, matches X-Hax sa2-mod-loader
  addresses). Second: SADX 2004 US `sonic.exe`. The 2011 SADX Steam exe is
  detected and reported as unsupported (convert with SA Mod Manager).
- Out of scope: controller, Chao simulation, rendering, audio, writing game
  assets.

## Workspace

```
sa-rewrite/
├── Cargo.toml                 workspace
├── crates/
│   ├── sa_formats/            pure format parsing, no game knowledge
│   │   ├── prs                PRS decompress + compress
│   │   ├── pak                SA2 PC .pak texture archives
│   │   ├── pvm                PVM/GVM archives, PVR/GVR decode to RGBA8
│   │   ├── ninja              NJCM/NJBM models, NMDM motions
│   │   └── landtable          level collision geometry + surface flags
│   ├── sa_data/               game knowledge on top of formats
│   │   ├── install            locate/identify installs by exe SHA-256
│   │   ├── physics            PhysicsData rows read from the exe file
│   │   ├── enums              characters, actions, upgrades, chao enums
│   │   ├── catalog            character/costume → model, motion, texture files
│   │   └── chao_save          ChaoData read/write (SA2, SADX 2004)
│   └── sa_ffi/                C ABI: staticlib + cdylib, cbindgen → include/sa.h
├── docs/                      research reports, facts tagged verified / docs-only
└── tests/ffi/                 C program exercising sa.h
```

## Data flow

1. `sa_data::install::open(path) -> Result<Game>` hashes the exe and returns
   a `Game` with a `GameKind` (`Sa2Steam`, `Sadx2004`) or an
   `Unsupported { reason }` error.
2. `Game::load_model(CharacterId, Costume) -> Result<Model>` resolves the file
   via `catalog`, reads it from the install, PRS-decompresses if needed,
   parses the Ninja model, and returns a node tree with meshes and texture
   references. Textures resolve through the matching PAK/PVM.
3. `Game::physics(CharacterId) -> Result<PhysicsData>` converts the table
   address to a file offset using the PE section headers, reads the 0x84-byte
   row, and decodes it into a typed struct (one i32 + 32 f32, field names from
   the mod-loader headers).
4. `chao_save::Sa2ChaoFile::read(&[u8])` parses 0x800-byte slots into typed
   `Chao` values; `write()` reproduces the input bytes exactly when nothing is
   changed (unknown bytes are kept verbatim).

## C ABI

- Opaque handles (`SaGame`, `SaMesh`, `SaChaoFile`), each with a `_free`/
  `_close`. The library never frees caller-owned memory.
- `#[repr(C)]` enums and POD structs; `sa.h` is generated by cbindgen.
- Every function returns `SaStatus`; `sa_last_error()` gives a thread-local
  message. Panics are caught at the boundary and returned as
  `SA_ERR_INTERNAL`.
- Meshes are returned as flat buffers: positions, normals, UVs, indices,
  per-submesh texture index, plus decoded RGBA8 textures.

Sample:

```c
SaStatus sa_game_open(const char* path, SaGame** out);
void     sa_game_close(SaGame*);
SaStatus sa_physics(SaGame*, SaCharacter, SaPhysics* out);
SaStatus sa_model_load(SaGame*, SaCharacter, SaCostume, SaMesh** out);
void     sa_mesh_free(SaMesh*);
SaStatus sa_chao_file_read(const uint8_t*, size_t, SaChaoFile** out);
SaStatus sa_chao_get(const SaChaoFile*, uint32_t slot, SaChao* out);
void     sa_chao_file_free(SaChaoFile*);
const char* sa_last_error(void);
```

## Error handling

Each crate has a `thiserror` error type (bad magic, out-of-bounds read,
unsupported exe, missing file). Parsers bounds-check every offset and never
trust pointers stored in files; malformed input returns an error, never
panics.

## Testing

- Fixture-free unit tests: PRS round-trip on random data plus hand-built edge
  cases; synthetic Ninja/PVR/landtable buffers; Chao slot build → write → read.
- Opt-in install tests (`--features game-tests`, `SA2_DIR`/`SADX_DIR`): every
  `.prs` in `gd_PC` decompresses; every catalog model parses with sane counts;
  every physics row decodes with sane values.
- Cross-check: a handful of physics bytes compared against REA's read of the
  same addresses in `sonic2app.exe`.
- C ABI test: `tests/ffi/main.c` built with `cc`, opens the game, loads Sonic,
  prints vertex count and physics.

## Known gaps carried from research

- SADX ChaoDataBase tail offsets were derived by counting and need checking.
- Upgrade → move gating and attack/damage logic are unverified (controller
  spec).
- Chao mechanics marked unverified in `docs/sa2_chao.md` (chao_sim spec).
